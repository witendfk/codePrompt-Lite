# 需求文档

## 1. / 指令选择功能

### 操作动线
1. **启动项目**
   - 启动项目后，向用户发起提问，用户可以输入内容
2. **触发条件**
   - 用户在输入时按下 `/` 键
   - `/` 键的前后必须没有空格（即该位置是单词的开始）
   - 触发后立即拉起指令列表

3. **列表展示**
   - 显示所有可用的指令列表
   - 列表在光标下方显示
   - 每项显示指令名称和简短描述

4. **选择操作**
   - **↑ / ↓ 键**：在列表中上下移动选择
   - **Tab 键**：确认当前选中的指令，自动填入输入框，**列表消失**
   - **继续输入**：用户可以继续输入字符，列表会根据输入内容实时筛选匹配的指令
   - **Esc 键**：关闭列表，保留用户已输入的内容

5. **指令执行时机**
   - 用户选择指令后，仅填入输入框，不立即执行
   - 用户按 Enter 确认发送后，再去解析指令并执行相应功能

6. **筛选规则**
   - 前缀匹配：用户输入 `/ex` 时，匹配以 `ex` 开头的指令

---

## 2. @ 文件选择功能

### 操作动线

1. **触发条件**
   - 用户在输入时按下 `@` 键
   - 触发后立即拉起文件列表

2. **列表展示**
   - 显示项目中的所有文件（排除 node_modules、.git 等目录）
   - 显示相对路径

3. **选择操作**
   - **↑ / ↓ 键**：在列表中上下移动选择
   - **Tab 键**：确认选择，文件以标签形式插入输入框（如 `@[filename]`），**列表消失**
   - **继续输入**：输入文件名进行筛选
   - **Esc 键**：关闭列表

4. **文件内容携带**
   - 当用户提交输入时，检测到 `@[filename]` 标记
   - 自动读取该文件内容
   - 将文件内容附加到用户问题中一起发送给大模型

---

## 3. 通用交互规范

- 同一时间只显示一个列表（指令列表或文件列表）
- 选择确认后列表立即消失，焦点回到输入
- 支持多次选择（如选择多个文件）
- 指令解析和执行只在用户按 Enter 发送后进行
